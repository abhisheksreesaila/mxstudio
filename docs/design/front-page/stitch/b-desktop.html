Common Inquiries

Go on, ask.

Modular MAX utilizes a state-of-the-art compiler graph engine and next-generation Mojo kernels that bypass PyTorch overhead completely. On modern GPUs, MAX achieves higher token throughput, rapid graph compilation, and unified zero-overhead memory scheduling.

Kernel Latency -34% vs standard runtimes
Unified Memory Zero-copy pinned paging
Compiler Target Native NVIDIA TensorIR

Ollama is great for simple single-user desktop testing, but lacks robust LAN proxy separation, multi-key security, and custom graph compiler speed. vLLM is optimized for multi-GPU cloud clusters. omxconsole is purpose-built for the single-box workstation developer wanting bare-metal MAX speed with complete LAN isolation.

Never. omxconsole runs 100% locally on your machine. Weights are downloaded directly to your NVMe cache from Hugging Face or loaded from local safetensors files. Zero metrics, telemetry, or model activations are ever sent externally.

Zero dollars. omxconsole is open-source (MIT). Porting a model typically takes 7 to 40 minutes of developer time using our scaffold tool ($ mxc port scaffold) which extracts PyTorch architectures and translates them to Mojo TensorIR nodes.

Apple Silicon (M-series) support is currently in development alongside Modular MAX's official Apple Silicon roadmap. Today, omxconsole requires Linux with NVIDIA GPUs (Ampere, Ada Lovelace, Hopper, or Blackwell).

Upcoming releases include automated speculative decoding harnesses, cross-workstation cluster pooling, and native quantized FP8 execution pipelines.
